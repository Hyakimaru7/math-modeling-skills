接收赛题和附件，交付可审阅论文、可运行代码与可追溯的计算记录。使用同一套问题编号贯穿模型、实验和论文。

## 工作方式

先读 [工作区协议](references/workspace.md)。在包含本 skills 包的工程目录使用已安装的 `mm`；源码运行方式为 `python scripts/mm.py`。CLI 执行结构化任务；由宿主 AI 理解题意、检索资料、选择模型、编写适配器及论文。按真实任务决定步骤和投入，不对普通计算逐步索取确认。

1. 检查用户给出的全部赛题、附件和已有工作。保留原件，建立小问依赖图，记录给定事实、假设和影响计算的歧义。已有工作区先执行 `mm status <工作区>`，保留人工改动。
2. 使用 `mm-analyze` 与 `mm-data` 完成结构化解释和数据核验。真实题目可以用 `mm init <工作区> --case custom` 建立接口示例，然后替换题目、数据、适配器和正文。完成替换前不得将示例结果描述为真实赛题答案。
3. 使用 `mm-model` 比较少量适合的候选方法。内置适配器只处理其文档明确支持的任务；其他题目使用 `mm-code` 编写当前题目的 `adapter.py`。不强行将任意赛题套成两个参考题型。
4. 为每个小问形成可用基线，在任务预算内改进。采用 `mm run <工作区> --until validate` 执行、修复并核验；失败后先定位原因。连续相同失败或预算耗尽时保留已验证产物和明确的未完成项。
5. 使用 `mm-paper` 撰写有证据支持的正文；摘要在结果确定后完成。按实际使用信息执行 `mm log-ai`，工具或模型版本未知时明确记为未知，不补造人工核验。
6. 执行 `mm run <工作区>` 完成论文和审阅。使用 `mm-review` 对照原题、数值、引用和 PDF 逐项检查。报告已完成范围、关键结果、遗留问题与使用路径；保留草稿状态，由队员最终审阅和提交。

## 模式与交付

快速模式优先覆盖所有小问的基线；标准模式增加模型比较与敏感性；深入模式根据剩余预算增加稳健性实验。模式是工作优先级，不代表跳过数据与结果核验。

交付 `problem.json`、`model.json`、代码、`solution.json`、`validation.json`、图表、`paper/manuscript.md`、`paper/paper.tex`、`paper/paper.pdf`、复现说明与实际使用记录。代码或假设变化后重新执行受影响流程；不要把旧 PDF 当作新结果。
